# 역전토익 홈페이지 — 소유권 인수인계

이 문서는 **사이트를 통째로 다른 사람에게 넘길 때** 무엇을 어떤 순서로 해야 하는지 적은 것이다.
넘겨받는 분에게 그대로 건네도 된다.

> **소유권은 한 덩어리가 아니다.** 코드는 GitHub, 사이트는 Vercel, 데이터는 Supabase,
> 로그인은 구글·카카오, 도메인은 Vercel 에 각각 따로 묶여 있다 — **여덟 곳이다.**
> 하나라도 빠뜨리면 그 조각만 Alan 계정에 남고, 그 계정이 사라지는 날 **그 기능만 조용히 죽는다.**

---

## 원칙 셋 — 먼저 읽을 것

**1. 한 번에 넘기지 않는다. `초대 → 확인 → 제거` 세 걸음이다.**
넘기자마자 나가면, 뭔가 빠졌을 때 **되돌릴 사람이 아무도 없다.** 각 서비스마다
새 주인을 **공동 소유자로 먼저 더하고**, 새 주인이 실제로 만져 본 뒤에, 그때 Alan 을 뺀다.
겹치는 기간은 넉넉히 둔다 (최소 1~2주, 가능하면 한 기수).

**2. 비밀값은 넘기지 말고 회전한다.**
비밀번호·API 키를 카톡으로 보내는 것이 인수인계가 아니다. 새 주인이 **새 값을 발급**해
갈아 끼우고, 옛 값을 폐기한다. 이건 새 주인을 위해서이기도 하지만 **Alan 을 위해서이기도 하다** —
넘긴 뒤 사고가 나도 Alan 손에 동작하는 키가 없어야 한다.

**3. 조용히 깨지는 것부터 본다.**
이 사이트에는 **깨져도 화면에 아무 오류가 안 뜨는** 연결이 네 개 있다 (아래 ★ 표시).
"열어 보니 멀쩡하네" 로는 확인이 안 된다 — 목록의 마지막 절을 실제로 눌러 볼 것.

| 5 | **Google Cloud — OAuth** | 구글 로그인 | Alan 계정이 지워지면 **학생 구글 로그인이 전원 불가** |

| 8 | **네이버 서치어드바이저** | 네이버 검색 노출 | 위와 같음 |
| 9 | **앱 안 `admin` 계정** | 관리자 화면 | ★**새 주인이 관리자 화면에 못 들어간다** (아래 함정) |

**코드 자체에는 Alan 개인 정보가 하나도 없다** (확인함) — 저장소에 박힌 것은 학원 정보(YBM 주소·네이버 예약·서면 주소)뿐이다.
그래서 **고칠 코드는 없고, 계정만 옮기면 된다.**

## 순서

### 0단계 · 준비 (새 주인이 한다)

계정 다섯 개를 만들고 Alan 에게 **가입한 이메일**을 알려 준다.

- GitHub · Vercel · Supabase · Google(구글 클라우드·서치콘솔 공용) · 네이버
- 카카오 로그인을 쓰고 있다면 Kakao Developers 도
- **결제 수단(카드)을 준비한다** — Vercel 도메인 갱신과 Supabase 요금이 여기서 나간다

### 1단계 · 앱 관리자부터 (제일 먼저, 제일 쉽다)

> **★ 함정: 마지막 관리자는 강등할 수 없다.**
> 이 사이트는 관리자가 한 명만 남으면 그 사람의 등급을 못 내리게 막아 두었다 (아무도 되돌릴 수 없게 되는 것을 막는 장치다).
> 그래서 **새 주인을 관리자로 올리기 전에는 Alan 을 뺄 수 없다.** 이것부터 해야 뒤가 풀린다.

1. 새 주인이 `https://winnertoeic.com/signup` 에서 **직접 가입**한다 (실명·휴대폰)
2. Alan 이 `관리자 모드 → 학생명단 → 그 사람 → 등급 변경 → 관리자` 로 올린다
3. 새 주인이 로그아웃했다 다시 들어와 `/admin` 이 열리는지 확인한다

**강사 계정도 함께 점검한다.** 이혜영·이영수 두 분이 이미 가입해 계시면 그대로 두면 된다.
아직 가입 안 한 분이 있으면 **그 이름 예약이 열린 채로 남아 있어, 그 이름으로 아무나 먼저 가입하면 강사 권한을 가져간다.**
인수인계 때 두 분 다 가입을 마쳐 두는 쪽이 안전하다 (자세한 내용은 `CLAUDE.md` 의 "강사 계정은 이혜영·이영수로 고정").

### 2~5단계 · 공동 소유자로 **더하기만** 한다 (아직 이전 아님)

| 서비스 | 하는 일 | 찾을 곳 |
|---|---|---|
| GitHub | 새 주인을 저장소 **Admin 권한 collaborator** 로 초대 | Settings → Collaborators |
| Vercel | 새 주인을 팀에 **Owner** 로 초대 | Team Settings → Members |
| Supabase | 새 주인을 조직에 **Owner** 로 초대 | Organization Settings → Team |
| Google Cloud | 새 주인 구글 계정을 프로젝트 **소유자(Owner)** 로 추가 | IAM 및 관리자 → IAM → 액세스 권한 부여 |
| Kakao | 새 주인을 앱 **팀원**으로 추가 | 내 애플리케이션 → 팀 관리 |
| 서치 콘솔 | 새 주인을 **소유자**로 추가 | 설정 → 사용자 및 권한 |
| 네이버 | 새 주인 계정으로 사이트를 **따로 등록**해도 된다 (아래 함정) | 웹마스터도구 |

> **★ 네이버만 다르다.** 우리 사이트는 소유확인 코드를 환경변수 `NAVER_SITE_VERIFICATION` 에서 읽어
> **한 번에 한 값만** 내보낸다. 새 주인이 자기 코드로 확인하려면 그 값을 새 것으로 바꾸고 재배포해야 하고,
> 그러면 **Alan 쪽 확인이 풀릴 수 있다.** 넘기는 김에 새 주인 값으로 갈아 끼우고 Alan 쪽은 포기하는 것이 깔끔하다.
> (구글은 DNS TXT 로 확인해 둬서 이 문제가 없다 — 소유자만 더하면 된다.)

### 6단계 · 확인 — **여기서 멈추고 새 주인이 직접 해 본다**

말로 "됐다" 가 아니라 실제로 세 가지를 해 본다:

- [ ] GitHub 에 아무 줄이나 고쳐 푸시 → **Vercel 배포가 도는지**
- [ ] Supabase 대시보드에서 `Database → Migrations` 목록이 보이는지
- [ ] 관리자 화면에서 학생 한 명을 열어 보기

세 개가 다 되면 그때 다음으로 간다. 하나라도 안 되면 **아직 넘기지 않는다.**

### 7단계 · 진짜 이전

순서가 중요하다. 이 순서대로 한다:

**① GitHub 저장소 이전**
`Settings → General → Transfer ownership` → 새 주인 계정으로.
옛 주소(`Alankim0130/turn_toeic`)는 GitHub 이 새 주소로 자동 연결해 주지만, 아래 두 연동은 **직접 다시 붙여야 한다.**

**② Vercel 프로젝트 이전**
프로젝트 `Settings → General → Transfer Project` → 새 팀으로.
- 옮긴 뒤 **Git 연결을 새 저장소로 다시 붙인다**
- **환경변수 13개가 다 넘어왔는지 눈으로 센다** (아래 목록). 빠진 것이 있으면 그 기능만 조용히 죽는다
- `vercel.ts` 의 **크론 2개**가 새 프로젝트에도 잡혔는지 확인한다

**③ ★ Supabase 의 GitHub 연동을 다시 붙인다 — 이게 제일 조용히 깨진다**
이 사이트는 **`main` 에 머지하면 DB 마이그레이션이 자동으로 적용**되도록 Supabase ↔ GitHub 을 연결해 두었다.
저장소를 옮기면 이 연결이 끊기는데, **배포는 성공으로 뜨고 DB 만 안 바뀐다.** 오류가 아무 데도 안 뜬다.
Supabase 대시보드 → `Integrations → GitHub` 에서 새 저장소로 다시 연결한다
(Deploy to production 켬 / production branch `main` / working directory `.`).
확인은 `Database → Migrations` 목록에 최신 파일이 보이는지로 한다.

**④ Supabase 프로젝트 이전**
`Project Settings → General → Transfer project` → 새 주인 조직으로.

> **★ 절대 "새 프로젝트를 만들어 데이터를 옮기는" 방법을 쓰지 말 것.**
> 프로젝트 주소(`grldodnbvznnnwpuunnt.supabase.co`)가 바뀌면 **구글·카카오에 등록한 로그인 콜백 주소가 전부 무효**가 되어
> 소셜 로그인이 통째로 깨진다. **조직만 옮기면 주소는 그대로**라 아무것도 안 깨진다.

**⑤ 도메인 이전 — 가장 중요한 한 줄**
도메인은 Vercel 에서 샀으므로 **Vercel 안에서 새 팀으로 옮긴다.**
- 옮긴 뒤 **자동 갱신이 켜져 있고 새 주인 카드가 걸려 있는지 반드시 확인한다**
- `winnertoeic.com` 은 사이트 주소일 뿐 아니라 **로그인 콜백·가입 확인 메일·검색 등록**이 전부 매달려 있다.
  이것 하나가 만료되면 나머지 일곱 개를 아무리 잘 넘겨도 소용이 없다

**⑥ Google Cloud · Kakao**
새 주인을 소유자로 올렸다면 프로젝트 자체는 그대로 두고 **Alan 만 빼면 된다** (OAuth 클라이언트 ID·시크릿이 그대로라 아무것도 안 깨진다).
새 주인이 **자기 구글 클라우드 프로젝트에 새로 만들고 싶다면** 새 클라이언트 ID·시크릿을 발급해
Supabase 의 Google 설정에 갈아 끼우고, 승인된 리디렉션 URI 에
`https://grldodnbvznnnwpuunnt.supabase.co/auth/v1/callback` 을 넣는다.

### 8단계 · Alan 제거 + 비밀값 회전

각 서비스에서 Alan 을 뺀다. **그 다음** 아래 표대로 비밀값을 갈아 끼운다.

| 비밀값 | 새로 만드는 곳 | 회전하면 생기는 일 |
|---|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` · `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase → Settings → API Keys | **키 구조에 따라 전원 로그아웃될 수 있다.** 대시보드에서 방식을 먼저 확인하고, **학생이 적은 시각**에 할 것 |
| `SUPABASE_DB_PASSWORD` | Supabase → Settings → Database | 없음 (앱은 안 쓴다 — 개발용 CLI 전용) |
| `SUPABASE_ACCESS_TOKEN` | supabase.com/dashboard/account/tokens | 없음 (개인 토큰이라 새 주인이 자기 것을 발급) |
| `VAPID_PRIVATE_KEY` · `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | `npx web-push generate-vapid-keys` | **강사님들의 푸시 알림이 전부 끊긴다** — 기기마다 `/admin/notifications` 에서 다시 켜야 한다. 급하지 않으면 그대로 둬도 된다 |
| `CRON_SECRET` | 아무 긴 임의 문자열 | 없음 (Vercel 환경변수만 바꾸면 된다) |
| `NAVER_WEBHOOK_SECRET` | 아무 긴 임의 문자열 | 네이버 예약 알림을 전달하는 쪽 설정도 같이 고쳐야 한다 |
| Google Client Secret | Google Cloud Console | 바꾸는 순간부터 Supabase 에 새 값을 넣을 때까지 **구글 로그인이 끊긴다** — 연달아 할 것 |
| Kakao Client Secret | Kakao Developers → 보안 | 위와 같음 |

**환경변수 13개 목록** (전체는 `.env.example`):
`NEXT_PUBLIC_SUPABASE_URL` · `NEXT_PUBLIC_SUPABASE_ANON_KEY` · `SUPABASE_SERVICE_ROLE_KEY` ·
`NEXT_PUBLIC_SITE_URL` · `GOOGLE_SITE_VERIFICATION` · `NAVER_SITE_VERIFICATION` ·
`NEXT_PUBLIC_VAPID_PUBLIC_KEY` · `VAPID_PRIVATE_KEY` · `VAPID_SUBJECT` ·
`NAVER_WEBHOOK_SECRET` · `CRON_SECRET`
(`SUPABASE_PROJECT_REF`·`SUPABASE_DB_PASSWORD`·`SUPABASE_ACCESS_TOKEN` 은 개발용이라 Vercel 에는 없어도 된다)

## 다 끝난 뒤 — 실제로 눌러 볼 것

화면이 열리는 것만으로는 확인이 안 된다. **하나씩 해 볼 것:**

- [ ] `https://winnertoeic.com` 이 열린다
- [ ] `https://winnertoeic.com/robots.txt` 의 `Host:` 가 `https://winnertoeic.com` 이다 (localhost·vercel.app 이면 재배포가 필요하다)
- [ ] **구글 로그인**으로 실제로 들어가진다
- [ ] **카카오 로그인**으로 실제로 들어가진다 (켜 두었다면)
- [ ] 새 이메일로 **회원가입** → 확인 메일이 실제로 온다
- [ ] 관리자 화면에서 학생 한 명이 열린다
- [ ] 코드를 한 줄 고쳐 `main` 에 머지 → **배포가 돌고** Supabase `Database → Migrations` 에도 반영된다
- [ ] 도메인 **자동 갱신이 켜져 있고** 결제 수단이 새 주인 것이다
- [ ] Vercel `Settings → Cron Jobs` 에 **크론 2개**가 보인다

## 넘어가지 않는 것 / 새로 해야 하는 것

- **SMTP (가입 확인 메일)** — 아직 안 붙였다. 기본 메일러는 시간당 몇 통에서 막혀, 방학에 학생이 몰리면
  **확인 메일이 조용히 실패하고 학생은 이유도 모른 채 가입을 못 끝낸다.** Resend 같은 외부 SMTP 를 붙이는 것이
  **출시 전 남은 유일한 필수 작업**이다 (`CLAUDE.md` 보안 점검 2번).
- **네이버 예약 알림 전달** — 네이버가 보내는 알림 원문을 우리 주소로 전달하는 설정이 Alan 쪽 어딘가(문자 전달·메일 규칙)에 있다면
  그것도 새 주인 쪽으로 옮겨야 한다.
- **Higgsfield** (아이콘·일러스트 제작 도구) — 만들어 둔 그림은 이미 저장소 안에 있으므로 **계정은 안 넘겨도 된다.**
  새 그림을 만들 일이 있을 때만 새 주인이 자기 계정을 쓰면 된다.
- **YBM 관련 계정** — 결제·수강신청은 YBM 공식 사이트에서만 일어나므로 이 사이트와 무관하다. 넘길 것이 없다.

## ★ 개인정보 — 그냥 넘기면 안 되는 부분

이 DB 에는 **학생 실명 · 휴대폰 번호 · 수강증 이미지 · 대학 · 학과**가 들어 있다.
소유자가 바뀌면 **이 정보를 다루는 주체가 바뀌는 것**이라, 계정만 옮기고 끝낼 일이 아니다.

- 학생들에게 **운영 주체가 바뀐다는 사실을 알려야 하는지** 확인할 것 (학원·YBM 쪽 규정과 함께)
- 가입 화면의 동의 문구에 적힌 수집·이용 주체가 지금 문구 그대로여도 되는지 확인할 것
- **나는 이 부분을 판단할 수 없다** — 학원 또는 YBM 의 개인정보 담당에게 물어보는 것이 맞다

수강증 원본은 판정 뒤 2개월이면 자동으로 지워지므로(크론), 넘길 시점에 쌓여 있는 양은 두 달치다.
