# 역전토익 홈페이지 인수인계 체크리스트

2026-10-05 기준. 이 파일은 저장소와 함께 인수자에게 넘어가는 원본이다. **사이트 관리자 메뉴 `운영 → 인수인계`** 가 이 파일을 그대로 보여 주고, 거기서 체크하면 사이트에 저장돼 알런과 인수자가 같은 진행 상황을 본다 (인수자는 2단계에서 관리자가 된 뒤부터). 같은 내용을 공유 문서(Claude Docs)로도 만들어 두었다. 사이트 설정(환경변수 · 자동 작업 · 저장소 · 외부 연결)이 바뀌면 이 파일과 공유 문서를 둘 다 고친다. 항목 번호(`0-1` · `3-B` …)는 체크를 저장하는 열쇠라 바꾸지 않는다.

넘길 것은 코드가 아니라 **계정**이다. 아래 단계를 위에서부터 하나씩 체크하면 사이트 · 데이터 · 도메인 · 로그인이 전부 인수자에게 넘어간다. 순서는 늘 **더하기 → 확인 → 빼기** — 인수자를 먼저 주인으로 더하고, 인수자 혼자 되는지 확인한 뒤, 마지막에 넘겨주는 사람(알런)을 뺀다. 거꾸로 하면 되돌려 줄 사람이 없다.

## 한눈에 보기

넘길 곳은 **열한 군데**다. 하나라도 빠지면 그 조각만 알런 계정에 남고, 그 계정이 닫히는 날 그 기능만 조용히 멈춘다. 가장 치명적인 것은 **도메인 갱신**과 **Supabase 요금**이다 — 둘 중 하나만 끊겨도 사이트 전체가 선다.

| 11 | 그 밖의 링크 | 네이버 예약 · YBM · 인스타그램 · 소개 영상 | 주인만 확인한다 | 그 버튼 하나만 깨진다 |

겹치는 기간을 넉넉히 둔다 — **최소 1\~2주, 가능하면 한 기수**(개강 → 등업 → 종강)를 함께 돌린다. 문제는 넘긴 날이 아니라 **다음 결제일과 다음 개강일**에 드러난다.

**코드에는 알런 개인정보가 없다** (2026-10-04 다시 확인). 고칠 코드는 개인정보처리방침의 책임자 칸 하나뿐이고(1단계), 나머지는 계정만 옮긴다.

## 0단계 · 준비

인수자가 계정을 만들고, 알런은 지금 상태를 기록해 둔다. 여기서는 아무것도 옮기지 않는다.

- [ ] **0-1 날짜와 기간을 정한다**
  1. 인수자와 함께 이 문서를 처음부터 끝까지 한 번 읽는다.
  2. 겹치는 기간을 달력에 적는다 — 최소 1\~2주, 가능하면 한 기수(개강 2주 전 시작 → 종강 뒤 마무리).
  3. 개강일 전후 사흘과 방학 첫달(1월 · 7월)은 피한다 — 수강증 등업이 몰린다.
- [ ] **0-2 인수자가 계정을 만든다** (전부 인수자 본인 이메일로)
  1. GitHub — github.com 가입. 아이디를 알런에게 알려 준다.
  2. Vercel — vercel.com 가입. 팀을 **Pro** 요금제로 만든다 (약관상 무료 Hobby 는 비상업용만 된다 — 4단계).
  3. Supabase — supabase.com 가입. GitHub 계정으로 가입해도 된다.
  4. 구글 — Gmail 계정 하나. 구글 클라우드와 서치 콘솔에 함께 쓴다.
  5. 카카오 — 카카오 계정으로 developers.kakao.com 에 로그인해 **개발자 등록**까지 한다 (안 하면 앱 멤버로 초대할 수 없다).
  6. 네이버 — 네이버 아이디 (서치어드바이저용).
  7. winnertoeic.com — 사이트에 회원가입하고 실명 · 휴대폰까지 넣는다 (2단계에서 관리자로 올린다).
  8. 개발을 이어 갈 사람이면 Claude 계정도 — 이 저장소는 Claude Code 로 만들었다.
- [ ] **0-3 결제 카드를 준비한다**
  1. Vercel(Pro 요금 · 도메인 해마다 갱신)과 Supabase(요금제)가 이 카드에서 나간다.
  2. 구글 클라우드 · 카카오 · 네이버는 지금 쓰는 범위에서는 돈이 들지 않는다.
- [ ] **0-4 알런이 지금 상태를 적는다** (부록의 ‘계정 기록표’에)
  1. 서비스마다 어느 이메일로 로그인하는지, 요금제가 무엇인지, 다음 결제일이 언제인지 적는다.
  2. Vercel — 대시보드 왼쪽 위 팀 이름 옆 요금제 표시(Hobby / Pro)와 Settings → Billing.
  3. Supabase — 조직 화면 → Billing 의 요금제(Free / Pro).
  4. 도메인 — Vercel → Domains → winnertoeic.com 의 만료일과 자동 갱신(Auto Renew) 켜짐 여부.
  5. 구글 클라우드 — 콘솔 위쪽 프로젝트 고르기에서 프로젝트 이름. 구글 로그인용과 유튜브 연결용 클라이언트가 같은 프로젝트에 있는지도 적는다.
  6. 카카오 — 디벨로퍼스 앱 이름, 카카오톡 채널의 현재 마스터가 누구인지.
- [ ] **0-5 되돌릴 길을 확인한다 (백업)**
  1. 코드 — GitHub 에 전부 있다. 따로 할 일은 없다.
  2. 데이터베이스 — Supabase → 프로젝트 → Database → Backups 에 날짜별 백업이 보이는지 본다. 안 보이면 넘기기 전에 요금제를 올리는 것을 검토한다.
  3. 파일(수강증 · 숙제 사진) — Supabase 저장소에 있어 프로젝트와 함께 간다. **PC로 내려받지 않는다** (개인정보가 늘어난다).
- [ ] **0-6 비밀값은 메신저로 보내지 않는다**
  1. 대부분은 넘길 필요가 없다 — Vercel 환경변수 · Supabase 설정 · DB 안 비밀은 서비스와 함께 옮겨진다.
  2. 필요하면 인수자가 **새 값을 만들어 바꾼다** (10단계). 옛 값을 전해 줄 일이 없다.
  3. 카톡 ‘나에게 보내기’ · 메모 앱에 적어 둔 비밀값이 있으면 목록만 만들어 두고, 다 넘긴 뒤 지운다.

## 1단계 · 개인정보 — 옮기기 전에

학생 실명 · 휴대폰 · 수강증 이미지가 데이터와 함께 넘어간다. 그래서 **데이터를 옮기는 3단계보다 먼저** 한다. 법적으로 꼭 알려야 하는지는 운영 주체가 바뀌는지에 달려 있어 전문가 확인이 필요하다.

- [ ] **1-1 운영 주체가 바뀌는지 정한다**
  1. 지금 이 사이트의 개인정보를 처리하는 주체를 적는다 (알런 개인 / 역전토익 강사 / YBM 서면 중 누구인가).
  2. 넘긴 뒤의 주체를 적는다.
  3. 주체가 바뀌면 개인정보 보호법 제27조(영업양도 등에 따른 개인정보의 이전 제한)의 ‘이전’에 해당할 수 있다. 같은 주체 안에서 담당자만 바뀌면 처리방침의 책임자만 고치면 될 수 있다.
  4. 어느 쪽인지 학원 · YBM 개인정보 담당 또는 변호사에게 **넘기기 전에** 확인한다. 떠난 뒤에는 고칠 권한이 없다.
- [ ] **1-2 (이전에 해당하면) 학생에게 미리 알린다**
  1. 알릴 내용은 세 가지다 — ① 개인정보를 이전한다는 사실 ② 받는 사람의 이름(법인이면 명칭) · 주소 · 전화번호 등 연락처 ③ 이전을 원하지 않을 때 할 수 있는 방법과 절차 (예: 문의 남기기로 계정 삭제 요청).
  2. 방법은 서면 · 전자우편 · 팩스 · 전화 · 문자 등으로 **미리 한 사람씩** 알리는 것이다 (시행령 제29조). 그렇게 알릴 수 없는 사람에 한해 홈페이지에 30일 이상 게시한다.
  3. 사이트 알림함만으로 충분한지는 확실하지 않다 — 1-1 확인 때 함께 묻는다. 학생 이메일 · 휴대폰은 관리자 화면 학생명단에 있다.
  4. 알린 날짜 · 방법 · 문구를 기록해 둔다.
- [ ] **1-3 개인정보처리방침의 책임자를 바꾼다** (코드 수정 한 곳)
  1. 파일은 `src/app/(public)/privacy/page.tsx` 다. 9항 ‘문의처’의 `개인정보 보호책임자: 역전토익 운영자` 를 실제 책임자(이름 또는 직책 · 연락처)로 바꾼다.
  2. 같은 파일 위쪽의 시행일(`EFFECTIVE`)을 바꾼 날짜로 올린다.
  3. 4항 위탁 목록(Supabase · Vercel · Google · Kakao)은 서비스가 그대로면 고칠 것이 없다. 나머지 항목은 2026-10-04 에 지금 사이트에 맞게 고쳐 두었다.
  4. Claude Code 에 “개인정보처리방침 책임자를 ○○○(연락처)로 바꿔 줘” 라고 하면 된다. main 에 머지하면 배포된다.
  5. 확인: https://winnertoeic.com/privacy 9항에 새 책임자가 보인다.
- [ ] **1-4 알런 PC에 남은 자료를 정리한다**
  1. **실물 수강증 30장**(`역전토익/수강증` 폴더, 2026-09-30 점검용)에는 학생 실명이 있다 → 넘기지 말고 지운다.
  2. 넘기면 좋은 원본 — `역전토익/강사프로필`(강사 사진 원본 · 누끼), `YBM_logo.png`, 브로슈어 · 편성표 이미지. 폴더째 인수자에게 준다.
  3. 비밀값을 적어 둔 메모 · 캡처의 목록을 만든다. 지우는 것은 10단계가 끝난 뒤다.

## 2단계 · 사이트 관리자

인수자를 winnertoeic.com 관리자로 먼저 올린다. 사이트는 **마지막 남은 관리자를 내리지 못하게** 막아 두었다 — 이걸 먼저 해야 10단계에서 알런을 내릴 수 있다. 알런의 등급은 지금 내리지 않는다.

- [ ] **2-1 인수자가 사이트에 가입한다**
  1. https://winnertoeic.com/signup 에서 이메일로 가입하거나 카카오 · 구글 간편 로그인을 누른다.
  2. 간편 로그인이면 이어서 뜨는 ‘가입 정보 입력’ 화면에 실명 · 휴대폰을 넣는다.
  3. 이메일 가입이면 확인 메일의 링크를 눌러야 끝난다. 메일이 안 오면 스팸함을 보고, 그래도 없으면 간편 로그인으로 가입한다 (기본 메일은 시간당 몇 통으로 막힌다 — 운영 ‘아직 안 끝난 일’).
- [ ] **2-2 알런이 인수자를 관리자로 올린다**
  1. 알런 계정으로 로그인 → 헤더의 `관리자 모드` → 메뉴 `학생` 묶음의 `학생명단`.
  2. `전체` 탭 → 검색칸에 인수자 이름 → 카드를 누른다 (학생 관리 화면이 열린다).
  3. `등급` 칸에서 `관리자` 를 고르고 저장한다. 인수자가 강사님 본인이면 그 강사 계정을 ‘관리자’로 올리면 된다 — 담당 과목(LC/RC)이 남아 반 담당 배정은 그대로이고, ‘불라방 링크’ 화면이 전체 수업을 보여 주는 것만 달라진다.
  4. 확인: 학생명단의 `강사·조교` 탭에 인수자가 관리자로 보인다.
- [ ] **2-3 인수자가 직접 들어가 본다**
  1. 인수자가 로그아웃했다가 다시 로그인한다.
  2. `관리자 모드` 를 눌러 대시보드가 열리는지 본다.
  3. 학생명단 · 등업 로그 · 반 편성을 하나씩 열어 본다.
  4. 메뉴 `운영` 묶음의 `인수인계` 를 연다 — 이 체크리스트다. 여기서 체크한 것은 알런과 인수자에게 같이 보인다.
- [ ] **2-4 강사 계정 둘이 다 가입돼 있는지 본다**
  1. 학생명단 `강사·조교` 탭에 이혜영 · 이영수 두 분이 `강사` 로 보이면 된다.
  2. 한 분이라도 없으면 위험하다 — 그 이름으로 먼저 가입한 사람이 저절로 강사가 된다(이름 예약). 넘기기 전에 두 분 가입을 끝낸다.
  3. 이혜영 강사의 실제 계정은 카카오 계정이다 (예전 이메일 계정은 2026-10-02 에 합쳤다).
- [ ] **2-5 알런 계정의 테스트 흔적을 지운다**
  1. 학생 화면을 보려고 알런 계정을 반에 배정해 둔 적이 있으면, 학생 관리 → `반 배정` 에서 해제한다. 안 지우면 대시보드 인원수에 섞인다.

## 4단계 · Vercel (사이트 서버) + 도메인

Vercel 에는 배포 · 환경변수 13개 · 자동 작업 3개 · 도메인 `winnertoeic.com` 이 묶여 있다. 도메인은 Vercel 에서 샀으므로 Vercel 안에서 프로젝트와 함께 옮긴다. 끝나면 **자동 갱신 카드가 인수자 것인지** 꼭 본다.

- [ ] **4-1 지금 요금제를 보고 방법을 고른다**

  2. **Pro 팀이면 → A (권장)**: 그 팀에 인수자를 Owner 로 더하고 카드를 바꾼 뒤 나중에 알런이 나간다. 프로젝트 · 도메인을 움직이지 않는다.
  3. **Hobby(무료)이면 → B**: Hobby 는 멤버를 둘 수 없고 약관상 비상업용만 된다. 인수자의 Pro 팀으로 프로젝트를 옮긴다.
- [ ] **4-2 (A) 팀에 인수자를 Owner 로 초대한다**
  1. 팀 → Settings → Members → Invite → 인수자 이메일 · 역할 `Owner`.
  2. 인수자가 초대를 수락한다.
  3. 인수자가 Settings → Billing 에서 결제 카드와 청구 이메일을 자기 것으로 바꾼다. 알런 카드는 10단계에서 지운다.
- [ ] **4-B (B를 고른 경우만) 프로젝트를 인수자 팀으로 옮긴다**
  1. 인수자가 Pro 팀을 만들고 **결제 카드를 먼저 등록**한다 — 대상 팀에 카드가 없으면 옮기기 전에 넣으라고 한다.
  2. 인수자가 그 팀에 알런을 멤버로 초대하고, 알런이 수락한다.
  3. 알런: 프로젝트 → Settings → General → 맨 아래 `Transfer Project` → 대상 팀을 고른다.
  4. 함께 옮겨지는 도메인 · 환경변수 목록이 뜨면 `winnertoeic.com` 이 있는지 보고 진행한다. 환경변수 · 자동 작업 · Git 연결 · 서버 지역(서울)도 함께 간다.

  6. 도메인은 Vercel 에서 산 것이라 **새 팀이 주인이 되고 갱신 요금도 새 팀에 청구**된다 (프로젝트가 쓰는 최상위 도메인일 때).
- [ ] **4-3 환경변수 13개가 다 있는지 센다**
  1. 프로젝트 → Settings → Environment Variables (Production).
  2. `NEXT_PUBLIC_SUPABASE_URL` · `NEXT_PUBLIC_SUPABASE_ANON_KEY` · `SUPABASE_SERVICE_ROLE_KEY` · `NEXT_PUBLIC_SITE_URL` · `GOOGLE_SITE_VERIFICATION`(비어 있어도 된다) · `NAVER_SITE_VERIFICATION` · `NEXT_PUBLIC_VAPID_PUBLIC_KEY` · `VAPID_PRIVATE_KEY` · `VAPID_SUBJECT` · `NAVER_WEBHOOK_SECRET` · `CRON_SECRET` · `YOUTUBE_CLIENT_ID` · `YOUTUBE_CLIENT_SECRET`.
  3. 빠진 것이 있으면 그 기능만 조용히 죽는다 (예: `CRON_SECRET` 이 없으면 Vercel 자동 작업 3개가 거절된다). 각각의 뜻은 부록 표.

  2. `/api/cron/daily-digest`(매일 21:00) · `/api/cron/purge-receipts`(매일 03:20) · `/api/cron/ybm-stats`(매일 04:10) — 한국 시간.

  4. `www.winnertoeic.com` 도 붙어 있으면 같은 팀에 있는지 본다.
- [ ] **4-6 사이트가 그대로 열리는지 본다**
  1. https://winnertoeic.com 이 열린다.
  2. https://winnertoeic.com/robots.txt 의 `Host:` 가 `https://winnertoeic.com` 이다.
  3. 프로젝트 → Deployments 맨 위 배포가 `Ready` 다.

  5. **클라이언트를 지우거나 새로 만들지 않는다.** 시크릿만 바꾸는 법은 10단계.
- [ ] **6-4 서치 콘솔: 인수자가 ‘확인된 소유자’가 된다**
  1. 알런: search.google.com/search-console → 속성 `winnertoeic.com` → `설정` → `사용자 및 권한` → 인수자 Gmail 을 `소유자` 로 추가한다. (화면에 따라 ‘소유자 관리’ 메뉴 안에 있다.) 이것만으로는 ‘위임된 소유자’라 2\~4 가 핵심이다.
  2. 인수자가 자기 이름으로 직접 소유 확인을 한다 — 서치 콘솔 → 속성 추가 → `도메인` → `winnertoeic.com` → 나오는 `google-site-verification=…` 값을 복사한다.
  3. 인수자가 Vercel → Domains → `winnertoeic.com` → DNS 레코드를 더한다: 종류 `TXT` · 이름 칸 **비움**(또는 `@`) · 값 = 복사한 문자열. 이름 칸에 `winnertoeic.com` 을 쓰면 `winnertoeic.com.winnertoeic.com` 이 되어 실패한다.
  4. 몇 분 뒤 서치 콘솔에서 `확인` 을 누른다.
  5. 왜: 속성에는 확인된 소유자가 한 명은 있어야 한다. 알런만 확인된 소유자인 채 알런이 빠지면 아무도 못 들어간다.
  6. 확인: 사용자 및 권한에서 인수자가 확인된 소유자다. `Sitemaps` 에서 `sitemap.xml` 이 ‘성공’인지도 본다.

## 7단계 · 카카오 (로그인 앱 · 상담 채널)

카카오 로그인 앱은 **지금 앱을 그대로 넘긴다.** 새 앱을 만들면 열쇠가 모두 바뀌어 Supabase 설정을 다시 해야 하고, 카카오로 가입한 학생들의 연결이 달라질 수 있다. 상담 채널은 링크만 쓰므로 주인만 정리한다.

- [ ] **7-1 카카오 디벨로퍼스 앱에 인수자를 멤버로 더한다**
  1. 인수자가 먼저 developers.kakao.com 에 카카오 계정으로 로그인해 개발자 등록을 마친다 (0-2).
  2. 알런: developers.kakao.com → `내 애플리케이션` → 이 사이트 앱 → 앱 설정의 `멤버` → 멤버 추가 → 인수자 카카오 계정.
  3. 인수자가 초대를 수락한다.
- [ ] **7-2 앱 소유자(Owner)를 인수자로 넘긴다**
  1. 같은 `멤버` 화면에서 소유자(Owner)를 인수자로 바꾼다. 메뉴 이름이 다르면 카카오 데브톡에서 ‘앱 owner 변경’으로 찾는다.
  2. 알런 카카오 계정으로 로그인할 수 있어야 한다 — 알런 계정이 살아 있을 때만 된다. 나중에 하려면 사업자 서류 등을 내고 카카오에 따로 요청해야 한다.
  3. 확인: 인수자 계정으로 앱을 열면 소유자로 보인다.
- [ ] **7-3 비즈 앱 · 로그인 설정이 그대로인지 본다**
  1. 앱이 **비즈 앱** 상태인지 본다 — 이메일 동의항목은 비즈 앱만 쓸 수 있다. 풀리면 카카오 로그인이 `KOE205` 오류로 막힌다. 풀렸으면 인수자가 비즈 앱 전환(개인 개발자 비즈 앱 · 본인 인증)을 다시 한다.
  2. 카카오 로그인 `활성화 ON`, Redirect URI `https://grldodnbvznnnwpuunnt.supabase.co/auth/v1/callback`.
  3. 동의항목: 닉네임 · 프로필 사진 · **카카오계정(이메일) 필수 동의**.
  4. 보안: Client Secret `사용함`. REST API 키 · Client Secret 은 Supabase 의 Kakao 설정에 들어 있으니 바꾸지 않는다 (바꾸는 법은 10단계).
  5. 확인: 시크릿 창에서 https://winnertoeic.com/login → `카카오 로그인` 으로 실제로 들어가진다.
- [ ] **7-4 카카오톡 상담 채널의 주인을 정리한다**
  1. 사이트의 `카카오톡 상담` 버튼은 채널의 채팅 주소(`pf.kakao.com/_xbtSTn/chat`)일 뿐이고, 열쇠나 연결은 없다.
  2. 카카오톡 채널 관리자센터(카카오비즈니스) → 이 채널 → `관리` → 관리자 초대 → 인수자 → 수락.
  3. 알런이 마스터면 마스터를 인수자로 넘긴다. 메뉴가 안 보이면 카카오비즈니스 고객센터에 문의한다.
  4. 채널 주인이 이미 강사님이면 할 일이 없다. 알런이 관리자로 들어가 있으면 10단계에서 빠진다.
  5. 채널 주소가 바뀌면 `src/lib/site.ts` 의 `kakaoChatUrl` 한 줄을 고친다.

## 8단계 · 네이버와 그 밖의 연결

네이버 서치어드바이저는 주인을 더하는 기능이 없어 인수자 계정으로 **새로 등록**한다. 나머지는 링크만 쓰는 곳이라 ‘누구 것인가’만 확인한다.

- [ ] **8-1 네이버 서치어드바이저를 인수자 계정으로 등록한다**
  1. 인수자: searchadvisor.naver.com → 웹마스터도구 → 사이트 등록 `https://winnertoeic.com`.

## 9단계 · 확인 — 인수자 혼자 해 본다

여기서 멈추고 **인수자가 자기 계정으로** 아래를 실제로 눌러 본다. 화면이 열리는 것만으로는 모른다 — 이 사이트에는 깨져도 오류가 안 뜨는 연결이 여럿 있다. 하나라도 안 되면 10단계로 가지 않는다.

- [ ] **9-1 배포와 DB 반영**
  1. 인수자가 작은 변경을 main 에 올린다 → Vercel Deployments 에 새 배포가 `Ready`.
  2. Supabase → Database → Migrations 맨 아래 줄이 저장소 최신 파일과 같다 (5-3).
- [ ] **9-2 로그인 세 가지**
  1. 시크릿 창에서 `Google 계정으로 계속하기` → 들어가진다.
  2. `카카오 로그인` → 들어가진다.
  3. 새 이메일로 회원가입 → 확인 메일이 온다. 안 오면 SMTP 문제다 (운영 ‘아직 안 끝난 일’ 1번).
- [ ] **9-3 관리자 화면과 파일**
  1. 대시보드 → 학생명단에서 학생 한 명을 연다.
  2. 등업 로그에서 수강증 하나를 열어 그림이 보인다 (파일 저장소가 살아 있다. 2개월 지난 것은 원래 지워져 있다).
  3. 반 편성 달력을 다음 달로 넘겨 본다 (저장은 하지 않는다).
- [ ] **9-4 관리자 알림**
  1. 인수자 휴대폰에서 사이트를 홈 화면에 추가한다 (아이폰은 이렇게 해야만 알림이 온다).
  2. 관리자 모드 → `알림 설정` → `이 기기에서 알림 받기` → `테스트 알림 보내기` → 알림이 온다.
  3. 다음 날 21:00 하루 요약이 온다 (그날 신청 · 숙제 · 가입이 0건이면 안 온다).
- [ ] **9-5 저절로 도는 작업**
  1. 대시보드 네이버 예약 위젯의 `마지막 확인` 이 10분 안쪽이다 — DB 가 사이트를 부르는 길이 산다.
  2. 랜딩 통계의 ‘N월 N일 갱신’이 오늘 또는 어제다 — Vercel 자동 작업이 산다.
  3. `유튜브 자동 연결` 화면에 강사님 두 분이 `연결됨` 이고, 다음 수업 때 오늘 회차 줄이 `송출 잡힘` 으로 바뀐다.
  4. 그 수업의 불라방 링크가 학생 화면에 들어가고, 오전 수업은 끝난 뒤 10분 안에 다시보기에 올라간다.

  1. Vercel · Supabase 결제 수단이 인수자 카드이고 청구 이메일이 인수자다.
  2. 도메인 자동 갱신이 켜져 있다 (4-5).
- [ ] **9-7 한 기수를 같이 돌려 본다** (권장)
  1. 다음 달 반 편성 → 시간표 → 반 개설을 인수자가 직접 해 본다 (운영 ‘매달 할 일’).

## 10단계 · 빼기 (맨 마지막)

9단계가 전부 된 뒤에만 한다. **인수자가 알런을 뺀다** — 그 한 번으로 인수자에게 진짜 주인 권한이 있다는 것이 증명된다. 그다음 알런이 알던 비밀값을 바꾼다.

- [ ] **10-1 사이트에서 알런을 내린다**
  1. 알런이 먼저 자기 휴대폰에서 관리자 모드 → `알림 설정` → `이 기기 알림 끄기`.
  2. 인수자: 학생명단 → `강사·조교` 탭 → 알런 → `등급` → `회원` → 저장. ‘마지막 관리자’ 안내가 뜨면 인수자가 아직 관리자가 아니다 — 2단계로 돌아간다.
  3. 알런 계정은 회원으로 내려 두기만 한다 — 지우면 알런이 처리한 기록의 ‘처리한 사람’이 비게 된다. 완전히 지우고 싶으면 몇 달 뒤 인수자가 Supabase → Authentication → Users 에서 지운다.
  4. 확인: 알런이 로그인해도 `관리자 모드` 가 없고 `/admin` 이 안 열린다.
- [ ] **10-2 서비스마다 알런을 뺀다** (인수자가 한다)
  1. Supabase — 조직 → Team → 알런 → Remove. Billing 에서 알런 카드를 지운다.
  2. Vercel — 팀 → Settings → Members → 알런 → Remove. Billing 에서 알런 카드를 지운다. B 방법이었으면 알런 원래 팀에 이 프로젝트 · 도메인이 남아 있지 않은지 본다.
  3. GitHub — 저장소 → Settings → Collaborators 에 알런이 있으면 Remove.
  4. 구글 클라우드 — IAM → 알런 줄의 연필 → 역할 삭제. 인수자가 소유자로 남아 있는지 먼저 본다.
  5. 서치 콘솔 — 설정 → 사용자 및 권한 → 알런 삭제. Vercel DNS 의 알런 쪽 TXT 는 지워도 되고 둬도 된다 (인수자 TXT 는 절대 지우지 않는다).
  6. 카카오 디벨로퍼스 — 앱 → 멤버 → 알런 삭제 (Owner 를 넘긴 뒤에만 된다).
  7. 카카오톡 채널 — 관리자에서 알런 삭제.
  8. 네이버 — 알런이 자기 웹마스터도구에서 사이트를 삭제한다 (선택).
- [ ] **10-3 알런이 알던 비밀값을 바꾼다** (권장 — 알런 손에 동작하는 열쇠가 남지 않게)
  1. 학생이 적은 밤에 한다. 바로 아래 표의 순서대로 하나씩 바꾼다 — 한꺼번에 바꾸면 무엇이 깨졌는지 모른다.
  2. 하나 바꿀 때마다 9단계의 그 확인을 다시 한다 — 구글 · 카카오 시크릿은 9-2(로그인), DB 안 비밀 · `CRON_SECRET` 은 9-5(저절로 도는 작업), 서비스 키는 9-4(테스트 알림 — 서버 열쇠로 보낸다).
  3. 표의 ‘바꿀 때 주의’ 칸을 먼저 읽는다 — 대부분은 새 값을 넣고 확인한 뒤에 옛 값을 지우고, 카카오처럼 재발급하는 순간 옛 값이 죽는 것은 연달아 한다. VAPID 키 3개는 바꾸지 않는다.

## 인수자가 알아야 할 운영

넘긴 뒤에도 사이트가 돌려면 강사 · 관리자가 **매달 해 줄 일**이 있다. 여기에 그 순서와 고장 났을 때 볼 곳, 아직 안 끝난 일을 모았다.

### 매달 — 다음 달 개강 2주 전쯤

1. **반 편성 달력** `/admin/sections` — 다음 달로 넘겨 개강일 · 종강일 · 월수금 · 화목금 · 특강 날짜를 찍고 저장한다. 개강일 · 종강일이 모든 권한의 기준이다.
2. **시간표** `/admin/timetable` — 그 달 시간표가 없으면 `N월 시간표 만들기`. 과정 A/B 는 앞 달에서 저절로 뒤집힌다. 주황 `미정` 칸이 없는지 본다.
3. **반 개설** `/admin/sections/new` — 강좌 × 시간대 × 트랙 표에서 한 번에 연다. 담당 강사는 과목으로 저절로 정해진다 (`담당 강사` 탭에서 확인).
4. **스터디** `/admin/study/plan` — 대면 · 단어 시간대를 넣고 연다. 비대면도 연다 (자료는 회차별로 한 번 올려 두면 매달 쓴다).
5. **특강** `/admin/lectures` — 신청 받기 · 정원. 신청 시작을 비우면 특강 7일 전 자정에 열린다.
6. **교재 · 계좌** `/admin/textbook-orders/setup` — 가격이나 입금 계좌가 바뀔 때만.
7. **등업 로그** `반 개설 대기` 탭 — 미리 받아 둔 다음 달 수강증이 반을 연 뒤 저절로 배정됐는지 본다.
8. **매 수업** — 강사님이 Zoom 에서 `YouTube에서 라이브`(일부 공개)를 켠다. 순서는 `유튜브 자동 연결` 화면에 있다.

### 방학달 (1 · 2 · 7 · 8월)

- 시간표를 **그 방학 브로슈어 시각 그대로** 적는다. 수강증의 수강시간과 글자까지 같아야 자동 등업된다.
- 방학 통짜 120분 반은 담당 강사가 비어 불라방 자동 연결이 안 된다 — 반 상세에서 링크를 손으로 넣는다.

### 매년

### 고장 났을 때 먼저 볼 곳

| 증상 | 먼저 볼 곳 |
| --- | --- |
| 사이트가 안 열린다 | Vercel → Deployments(최근 배포 실패) · 도메인 만료 · Supabase 프로젝트 상태·요금 |
| DB 변경을 머지했는데 화면이 안 바뀐다 | Supabase → Database → Migrations · GitHub 연결(5-3) · 파일 번호 앞 14자리가 겹치는 파일 |
| 네이버 예약 알림이 안 온다 | 대시보드 네이버 위젯 `마지막 확인` · SQL `select status_code, left(content, 200), created from net._http_response order by created desc limit 10;` |

### 아직 안 끝난 일 — 알런이 떠나기 전에 해 두면 좋다

1. **SMTP — 출시를 막는 유일한 필수 항목.** Supabase 기본 메일은 시간당 몇 통에서 막혀, 방학에 학생이 몰리면 확인 메일이 조용히 실패한다. Resend 같은 외부 SMTP 를 Supabase → Authentication 의 SMTP 설정에 넣는다.
2. 개인정보처리방침의 책임자 (1-3).
3. 선택 — 가입 · 로그인 봇 막기(CAPTCHA) 또는 IP 속도 제한. 학원 와이파이는 한 IP 로 보여 숫자를 넉넉히 잡는다.
4. 정하지 않은 규칙 — 편성을 고쳤을 때의 녹화본 · YBM 후기 자동 수집 · 숙제 미제출 기준 · 비대면 미인증 제재 · 등록생 명단 대조. `CLAUDE.md` 맨 아래 ‘미확정’에 있고, 정하기 전에는 만들지 않는다.

### 개발을 이어 갈 사람에게

- `CLAUDE.md` 를 먼저 읽는다 — 특히 맨 앞의 ‘등급 체계’와 ‘작업 원칙’. 어기면 권한 구멍이 난다. 알런에게 물어볼 수 없으니 그것이 유일한 기록이다.
- 고친 뒤 확인은 넷 — `npx tsc --noEmit` · `npx eslint src` · `npx vitest run` · `npm run build`.
- DB 변경 파일은 마지막 번호보다 뒤 번호로 만든다 (`ls supabase/migrations | tail`). 같은 번호면 오류 없이 건너뛴다. 저장소는 공개다 — 계좌번호 · 학생 실명 · 비밀값을 코드나 문서에 적지 않는다.
- 아이콘 · 그림 · 강사 캐리커처는 Higgsfield 로 만들어 저장소(`public/`)에 들어 있다. 그 계정은 넘길 필요가 없고, 새 그림이 필요할 때만 인수자 계정을 쓴다.

### 도메인을 바꾸게 되면 (지금은 계획 없음)

주소가 다섯 군데에 따로 적혀 있다. 하나라도 빠지면 그 기능만 오류 없이 멈춘다.

1. Vercel — 새 도메인을 프로젝트에 붙이고, `NEXT_PUBLIC_SITE_URL` 을 바꾼 뒤 **다시 배포**한다 (robots.txt · sitemap.xml 은 배포 때 주소가 박힌다).
2. Supabase → Authentication → URL Configuration — Site URL 을 바꾸고 Redirect URLs 에 `https://새주소/**` 를 더한다. 빠뜨리면 새 주소로 온 사람만 카카오 · 구글 로그인이 깨진다.
3. Supabase SQL Editor — `update private.app_config set value = 'https://새주소' where key = 'site_url';` (끝에 `/` 없이). 안 바꾸면 네이버 예약 확인 · 유튜브 감지가 멈춘다.
4. 구글 클라우드 — 유튜브용 클라이언트의 리디렉션 URI 에 `https://새주소/api/youtube/callback` 을 더하고, 동의 화면의 홈페이지 · 개인정보처리방침 주소 · 승인된 도메인을 바꾼다.
5. 서치 콘솔 · 네이버 서치어드바이저에 새 주소를 등록하고 사이트맵을 다시 낸다. 옛 도메인은 한동안 새 주소로 넘기고 갱신해 둔다.
