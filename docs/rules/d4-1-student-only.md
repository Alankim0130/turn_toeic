### 4-1. 수강생전용 — 보이지만 수강생만 쓴다 (2026-09-15 Alan 요청)

- 소개 페이지 `/student` 와 메뉴의 "수강생전용" 아래에 **8개**: **불라방교재주문** · 불라방 · 다시보기 · 숙제업로드 · 스터디 · **특강신청** · **수업자료실** · LC음원듣기.
  **불라방교재주문이 맨 앞이다** (2026-10-07 Alan — "불라방 교재주문을 맨 위로 올려줘") — `/student` 카드 · PC 수강생전용 메뉴가 이 순서를 따른다 (햄버거 서랍은 `NAV_DRAWER` 묶음이 따로 정한다).
  수업자료실은 2026-10-05 에 추가했다 (도메인 규칙 7-4).
  목록과 설명은 `src/lib/site.ts` 의 `STUDENT_FEATURES` 한곳에서 관리한다 (메뉴·햄버거·소개 페이지·잠금 안내가 전부 여기서 나온다).
  특강신청은 2026-09-16 에 추가했다 — 내 시간표 안에만 두었더니 학생이 찾지 못했다.
- 비수강생에게도 **메뉴와 소개는 보인다** (잠금 표시). 누르면 소개 페이지의 해당 카드로 가서 수강생이 되는 방법을 안내한다.
  "수강생이 되면 이런 걸 쓸 수 있구나"를 알게 하는 것이 목적이다.
- 판정 (`getStudentAccess`): **불라방교재주문만 예비등록생부터, 나머지 6개는 개강일~종강일 안의 배정이 있을 때** (`STUDENT_FEATURES[].access`).
  **강사·관리자·조교도 같은 판정이다** (2026-10-02 Alan "수강생전용 페이지를 전부다 개강일에 맞춰서 오픈" — 2026-09-16~10-02 에는 크루면 무조건 열렸는데,
  10월 반에 배정된 관리자가 개강 전 학생 모드에서 모든 것이 열려 학생이 무엇을 보는지 알 수 없었다). 열어 볼 권한(RLS)은 그대로고 학생 모드 화면만 학생과 같다.
  크루가 배정 없이 들어오면 잠금 화면이 `강사·조교 계정은 반에 배정돼야 학생 화면이 열려요` + 학생명단 링크다 (`unlockState = "crew"`). 테스터는 반에 배정해서 본다.
  조교에게는 학생명단 링크 대신 "반 배정은 강사님께 부탁해 주세요" 다 (2026-10-03 — 조교는 학생명단 · 반 배정이 없다).
  스터디·특강은 2026-09-15~10-02 에 예비등록생부터였다 (Alan 확인 전 기본값) — **되돌리지 말 것.** 교재주문만 남긴 까닭은 첫 수업 전에 책이 와야 해서다.
  그때 남은 문구 둘을 2026-10-03 에 고쳤다 (Alan — `/student` 의 "스터디는 지금 신청할 수 있어요" 를 보고 "아니야. 삭제해줘"): `/student` 상태 띠는 `예비등록생이에요. N월 N일 개강일부터 모든 기능이 열려요.` 까지이고,
  `/study` 의 예비등록생 안내는 `N월 N일 개강일부터 신청할 수 있어요` 다 (예전 "개강 전(예비등록생)에도 신청할 수 있어요"). **예비등록생에게 스터디·특강을 "지금" 할 수 있다고 적지 말 것.**
- 기능 페이지 주소로 바로 들어와도 `studentGate()` 가 잠금 안내를 보여준다. 화면 안내일 뿐 실제 데이터 보호는 RLS 가 한다.

### 5. 예비등록생 — 개강 전 수강증 업로드

- 학생은 **개강일 전에도 수강증을 올릴 수 있다.**
- OCR 검증을 통과하면 `enrollment_orders.status = 'preliminary'`로 기록되고,
  **"N월 예비등록생"**으로 표시된다.
- 예비등록생은 아직 `student`가 아니다. 불라방·다시보기 접근 불가.
- **개강일이 되면 자동으로** `active` + `role = 'student'`로 전환된다.
