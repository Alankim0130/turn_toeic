### 6-2. 비대면 스터디 인증 · 학생 알림함 (2026-09-18 Alan 요청, 마이그레이션 20260918150000)

> "비대면 스터디를 신청한 학생은 자료를 받아 풀 수 있고 **인증을 항상** 해야 한다. 인증은 비대면 스터디 페이지에서.
>  인증을 안 했으면 강사 모드에서 날짜별로 누가 안 했는지 보고 그 학생에게 메시지를 보낼 수 있게.
>  + 학생 계정에서 선생님에게 알림을 받을 수 있는 공간."

- **인증** = 자료(날짜) 하나에 학생 1건, 풀이 사진 1~10장(+메모 300자). `study_checkins` · `study_checkin_files`, 버킷 `study-checkins`
  (숙제와 같은 규칙: 본인 폴더 업로드, 본인·스태프 조회). 화면은 `/my/study` 의 자료 줄마다 `CheckinPanel` — `미인증` 배지 + [인증하기],
  인증하면 `인증함 · 시각 · 사진 N장` + [지우고 다시]. **학생은 자료 · 본인 · 메모 칸만 넣는다**(칸 단위 grant — 2026-10-29, 마이그레이션 20261029100000: 그전에는 표 전체 insert 권한이라
  API 로 처음부터 '선생님 확인 완료' · 가짜 코멘트인 인증을 넣을 수 있었고 강사 게시판의 '확인 전' 에서 빠졌다. 확인된 인증에는 사진 줄을 더하거나 저장소에서 사진을 지우지도 못한다). 자격은 RLS 가 본다: **신청한 스터디의 자료 · 자료 날짜 도래 · 지금 수강 중**.
  선생님이 확인하면(아래 게시판) `선생님 확인 완료` 배지가 서고 **[지우고 다시] 가 사라진다** — DB 도 확인된 인증은 학생이 못 지운다(사진 줄도). 코멘트는 자료 줄에 `선생님 코멘트` 로 펼쳐 둔다.
  숙제업로드(레벨 × RC/LC, 규칙 7)와는 별개다 — 그쪽은 정규 수업 숙제, 이쪽은 비대면 스터디 인증.
- **비대면스터디 인증 게시판** `/admin/study-checkins` (관리자 메뉴 `학습 → 비대면스터디 인증`, 2026-10-08 Alan — "비대면 스터디도 숙제 점검 처럼 게시판이 필요합니당~
  "비대면스터디 인증" 카테고리 하나 만들어줘. 별도의 페이지가 있으면 좋겠어", 마이그레이션 20261008140000). 그때까지 강사 · 조교 화면에는 **인증했는지 · 사진 몇 장인지만** 보였고
  학생이 올린 사진과 메모를 볼 길이 없었다 (`/files/checkin/{파일 id}` 도 없었다). 두 화면이다 (`?view=`):
  - **게시판**(기본) — 숙제점검처럼 **인증 한 건이 한 줄**(`CheckinBoard` — 아바타 · 이름 · `확인 완료` 배지 · 반 · 사진 N장 · 메모 · 인증 시각)이고 **자료 날짜(회차)로 묶는다**
    (`2회차 · 10월 7일 (수)` + `인증 n / 신청 N · 확인 전 m` — 비대면 인증은 수업일마다 한 건이라 날짜를 빼면 줄마다 어느 날 것인지 읽어야 한다). 최근 날짜 · 최근 인증이 위.
    기본은 **확인 전만**, `확인 완료 포함` 체크박스로 다 본다 (숙제점검의 `점검완료 포함` 과 같은 자리 · 같은 모양). 줄을 누르면 **상세 팝업** — 풀이 사진을 `n / N` 으로 넘겨 보고
    (`PhotoViewer` — 숙제점검과 함께 쓰는 뷰어, `/files/checkin/{id}?w=1200`) · 학생 메모 · 코멘트(선택, 1,000자) + **`확인 완료 · 알림 보내기`** → 학생 알림함(`study_checked`)으로 간다.
    확인을 보내면 팝업이 닫히고 그 줄이 목록에서 빠진다. **확인 전인 인증만 바꾼다**(`.eq("status", "submitted")`) — 두 사람이 같은 인증을 동시에 눌러도 알림이 두 번 가지 않는다.
    `확인 취소` 는 코멘트도 지우지만 이미 보낸 알림은 그대로 둔다 (숙제 점검 취소와 같다).
  - **한눈에 보기** — 아래 ① 격자 · ② 날짜별 카드(독촉 알림)를 그대로 옮겼다 (`CheckinRoster`). 스터디 신청자 화면(`/admin/study`)의 비대면 탭에는 이리 오는 카드만 남았다.
  - 상태는 `study_checkins.status`(`submitted` 확인 전 · `checked` 확인 완료) · `checked_by` · `checked_at` · `feedback` — 정책 `study_checkins: 스태프·조교 확인`(칸 단위 grant 라 그 넷만 바뀐다).
    **숙제(`homework_submissions`)와는 여전히 표 · 화면 · 알림 종류가 따로다** — 모양만 같고 사진 뷰어만 함께 쓴다.
  - **조교도 쓴다** — 스터디는 조교가 운영하고(2026-10-03) 인증 현황 · 독촉은 그때부터 조교 일이었다. 저장소 `study-checkins` 조회를 crew 로 넓혔다(그전에는 조교 세션으로 사진 서명 주소가 안 나왔다).
    조교 · 관리자가 확인한 알림에는 **그 사람 이름이 남지 않는다** — 강사가 아니면 전부 (등급 체계 9-1 · 도메인 규칙 3 "조교가 학생에게 보내는 알림", 2026-10-08 저녁 20261008160000). 이름은 `getProfileNames` 로 읽는다 (조교는 profiles 를 못 읽는다).
  - 인증은 그 달 자료 id 로 **1,000줄씩 나눠 읽는다** — 예전 인증 현황은 `study_checkins` 를 거르지 않고 통째로 읽어(PostgREST 상한 1,000줄) 몇 달이 쌓이면 줄이 조용히 빠졌을 것이다.
- **인증 현황(한눈에 보기)** = 위 게시판의 `한눈에 보기` 탭(`CheckinRoster` — 2026-10-08 전에는 `/admin/study` 비대면 탭 위). **조교도 본다 · 보낸다** (2026-10-03 Alan "스터디를 조교가 운영한다" — 그전에는 자료 · 인증 조회가
  스태프에게만 열려 조교 화면에는 빈 표가 떴다. 조교가 보내는 독촉은 정책 `student_messages: 조교 발송` 이 `study_checkin` · 자기 이름으로만 받는다). 두 가지를 함께 보여 준다:
  ① **한눈에 보기 — 학생 × 날짜 격자** (2026-09-19 Alan: "학생들이 비대면을 신청하고 난 뒤, 인증을 했는지 안했는지
     강사모드에서 **한번에 쭈욱 확인**이 가능하면 좋겠어"). 행이 신청자, 열이 자료 날짜, 칸이 인증(분홍 체크)·미인증(회색 점)이고
     줄 끝에 `n / N`. **미인증이 많은 학생이 위로** 온다. 자료가 한 달에 18~19개라 가로 스크롤은 어쩔 수 없어 **이름 칸만 왼쪽에 고정**한다.
     칸 안에 `sr-only` 자식을 두지 말 것 — `position:absolute` 라 가로 스크롤 상자를 빠져나가 **페이지 전체가 옆으로 밀린다**
     (320px 에서 15px 넘쳤다). 설명은 `aria-label`·`title` 로 단다. 체크 표시는 12px 라 **도형(인라인 SVG)** 이다.
  ② **날짜별 카드**: 자료마다 `인증 n · 미인증 m / 신청 N`, 펼치면 학생 표(이름 · **반** · 인증 시각 · 사진 수).
     `미인증 m명에게 알림 보내기` → 기본 문구(`missingCheckinMessage`, 날짜·할 일)를 고쳐 보낸다. 받는 학생은 체크로 뺄 수 있다.
- **이름 옆은 등급도 연락처도 아니라 `반` 이다** (2026-09-19 Alan — "수강생이라는 뱃지가 아니라 무슨 수업을 듣고 있는지.
  650 주5일 10:00-12:10 이런거"). **등급을 적지 말 것** — 스터디는 그 달 반에 배정된 수강생만 신청할 수 있어서
  (`private.is_term_enrollee`, 예비등록생 포함) 여기 선 사람은 **전원 같은 등급이다.** 자리만 먹고 아무것도 가리지 못한다.
  두 표(한눈에 보기 · 날짜별)가 같은 값을 쓴다.
  **스터디 신청자 화면에는 전화번호를 어디에도 두지 않는다 — 되살리지 말 것** (2026-09-23 Alan — 신청자 표의 `연락처` 칸을 보고
  "이 번호가 필요없다는 말이야"). 대면·단어의 시간대별 표와 비대면 신청자 표 모두 `# · 이름 · 신청일 · 관리` 이고, 신청 조회도 전화번호를 읽지 않는다.
  같은 날 출석 명단에서도 연락처를 뺐다 (도메인 규칙 7-2). 연락이 필요하면 학생명단(`/admin/students`)에서 본다.
  - 이름은 `sectionChip(반, week5, { withTerm: false })` 로 짓고 **달(`9월`)은 뺀다** — 화면 전체가 한 기수라
    줄마다 되풀이하면 정작 봐야 할 레벨·시간이 뒤로 밀린다. **주5일은 한 줄로 합친다**(`collapseWeek5`, 도메인 규칙 1) —
    짝은 **그 학생이 듣는 반 안에서만** 찾을 것. 그 기수의 배정만 남긴다 (지난달 반까지 적으면 여러 반을 듣는 것처럼 보인다).
  - **좁은 화면에서는 `반` 칸을 접어 이름 아래로 내린다**(`sm:table-cell` ↔ `sm:hidden`) — 칸으로 두면 320px 에서
    `인증 시각 · 사진 N장` 에 밀려 **이름이 한 글자씩 세로로 쪼개진다**(김/민/수). 가로 스크롤을 하나 더 만들지 않는다.
- **인증을 안 한 학생에게 자료를 막는 규정은 아직 없다** (2026-09-19 Alan — "인증이 제대로 이뤄지지 않으면 더이상 스터디자료를
  받을 수가 없어. **정확한 규정은 아직 확인을 안 해봤지만**"). 막는 코드를 임의로 넣지 말 것 — 지금은 현황을 보여 주고 알림을 보내는 데까지다.
- **학생 알림함** `/my/notifications` (`student_messages`): 스태프가 보낸 알림 **+ 수업 시작 알림**(크론, 규칙 1). **앱 안에서** 보인다 —
  문자·알림톡은 없다. **휴대폰 푸시는 `live_start` · `homework_missing` 두 종류만** 학생이 켠 기기로도 간다 (2026-10-15, 규칙 8-1 — 알림함 맨 위 카드에서 켠다). 종류는 열이다 —
  `general` · `study_checkin`(비대면 인증 독촉) · `homework_checked`(숙제 점검완료) · `live_start`(불라방 수업 시작) · `contact_reply`(문의 답변, 2026-09-30 — 규칙 7-3) ·
  `attendance`(결석 안내, 2026-10-01 — 규칙 7-2, 버튼 `내 출석 보기`) · `merge_choice`(남길 계정 고르기, 2026-10-02 — 규칙 3-1) ·
  `textbook`(불라방 교재비 안내, 2026-10-02 — 규칙 7-1, 버튼 `교재 주문하기`) · `study_checked`(비대면 인증 확인 완료, 2026-10-08 — 위 게시판, 버튼 `내 스터디 보기`) ·
  `homework_missing`(숙제 미제출 안내, 2026-10-08 — 규칙 7 "숙제 미제출 알림", 버튼 `숙제 내러 가기`. **숙제제출 화면에서 '알림 안 받기' 를 누른 학생에게는 가지 않는다** — 2026-10-15, 10-14 하루는 거꾸로 신청한 학생에게만).
  **새 종류를 더하면 DB check(`student_messages_kind_check`)도 함께 늘리고 알림함 버튼도 단다** — `study-checkin.test.ts` 가 DB 의 종류마다 알림함에 버튼이 있는지 본다.
  **종류마다 서로 다른 일이라 할 일로 가는 버튼이 다르다.** `/my` 에 "새 알림 N개" 띠, 서랍 마이페이지 묶음과 바로가기에 `알림`.
  열면 읽음(`read_at`)으로 바뀐다
  (학생은 그 칸만 바꿀 수 있다 — 컬럼 grant). 학생은 스태프 프로필을 못 읽으므로 보낸 이름은 `sender_name` 에 박아 둔다.
  인증 알림(`kind = study_checkin`)에는 "내 스터디에서 인증하기" 버튼이 붙는다. 답장은 없다 — 학생은 연락하기로.
- 계정 통합(`private.merge_accounts`)이 인증·알림함도 옮긴다.
