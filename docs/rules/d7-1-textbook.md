### 7-1. 불라방 교재주문 — 강사가 교재·계좌를 등록한다 (2026-09-21 Alan 요청, 마이그레이션 20260921110500)

> "교재비를 받는 계좌번호와 교재 과목 등록은 강사가 직접 할 수 있도록 해보자." (첫토익 교재주문을 옮겨 오며)

- **강사·관리자가** `/admin/textbook-orders/setup` 에서 등록한다 — 입금 계좌(`textbook_accounts`: 은행·계좌번호·예금주·이름표) ·
  교재(`textbook_items`: 이름 · 레벨(비우면 모든 레벨) · 가격 · 받는 계좌 · 설명) · 배송비·기본 계좌·안내 문구(`textbook_settings`, 한 줄).
  **가격·계좌를 코드에 적지 않는다** (첫토익은 앱 설정 파일에 있어 바꿀 때마다 배포해야 했다). 조교는 주문 처리만 하고 이 화면은 못 연다.
- **학생 흐름**: **내 반 교재가 그대로 들어가 있다 — 고르지 않는다**(아래 "주문할 교재는 내 반 교재 그대로") → **받는 방법**(택배 · 현장수령 — 아래 "현장수령")을 고른다 → 합계와 **계좌별 입금액**이 보인다 → 입금하고 **입금자명**을 적어 주문.
  - **택배 배송지는 주소 + 상세 주소 두 칸이고 둘 다 필수다. 우편번호 · 요청사항 칸은 없다** (2026-10-07 Alan — "우편번호 필요없고 본인 주소만 기입하게 해줘. 그리고 상세주소는 선택이 아니라 필수로 들어가야해. 그래야지 배송을 할 수 있지. 요청사항도 없애줘" — 그전에는 우편번호 · 상세 주소 · 요청사항이 선택 칸이었다).
    상세 주소를 반드시 받는 것은 **폼과 서버 액션**(`submitTextbookOrder` — 비면 "상세 주소(동 · 호수)를 적어 주세요")이 본다. **DB 함수 `create_textbook_order` 는 손대지 않았다** —
    금액 · 자격을 지키는 함수라 예전처럼 상세 주소가 비어도 받고, 우편번호 · 메모 인자에는 앱이 빈 값을 보낸다 (현장수령 시각 범위를 서버 액션이 막는 것과 같은 규칙).
    표의 칸(`postal_code` · `memo`)도 그대로라 **예전 주문의 우편번호 · 메모는 강사 · 조교 교재주문 화면에 그대로 보인다.** 현장수령이면 두 칸이 숨고 필수가 꺼진다.
  - **주문 폼은 `onSubmit` 에서 직접 보낸다** (2026-10-07 확인) — `<form action>` 으로만 보내면 React 19 가 action 이 끝난 뒤 폼을 초기화(`form.reset()`)해서
    교재 체크 · 받는 방법 · 시각 칸이 처음 그린 모양으로 돌아간다. 분홍 카드 · 합계는 고른 그대로인데 실제로 보내는 값이 비어, 휴대폰 번호 오타 같은 서버 오류 뒤
    고쳐 다시 누르면 "주문할 교재를 하나 이상 골라 주세요" 가 떴다 (시험 DB 로 재현). 같은 이벤트 안에서 `startTransition` 으로 보내면 React 가 초기화하지 않고
    버튼의 '주문하는 중…'(`useFormStatus`)은 그대로 켠다. **제어하는 체크박스 · 라디오 · 고르기 칸이 있고 서버 오류 뒤에도 남는 폼이면 같은 함정이다**
    (상태로 쥔 글 칸은 React 가 값 속성을 맞춰 두어 그대로다 — 체크 · 고르기 칸과 `defaultValue` 만 준 칸이 처음 모양으로 돌아간다).
    → 2026-10-29 부터 **`onSubmit={submitWithoutReset(action)}`**(`src/lib/form-submit.ts`) 한 줄이고, 같은 꼴의 폼 열네 곳에 걸었다 (`form-submit.test.ts` — 아래 "2026-10-29 전체 버그 점검" 21).
  강사가 통장과 대조해 **금액확인**, 조교가 보내고 **배송완료**(+ 송장번호, 선택) — 아래 "배송 단계". 상태는 `requested → confirmed → shipped` + `cancelled`.
  금액확인 전에는 학생이 취소할 수 있다.
