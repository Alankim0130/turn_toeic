### 7-3. 문의 답변 (2026-09-30 Alan, 마이그레이션 20260930120000)

> "지금 이주은 이라는 학생이 문의를 해줬는데, 강사가 직접 답변을 해주는 공간이 없어. 혹시 비회원이라서 답변장소가 없는건가?
>  만약 그렇다면, 회원가입을 하면 답변을 여기로 바로 받을 수 있다고 안내도 같이 나가면 좋을 것 같아."

- 그때까지는 **회원·비회원 가릴 것 없이 답변 칸 자체가 없었다** (상태만 바꿨다). 그 문의는 비회원 문의였다 (2026-09-30 운영 DB — 문의 2건 모두 비회원).
- `/admin/contacts` 카드마다 답변을 적는다 → `contact_messages.reply · replied_at · replied_by`, 상태는 `답변 완료`.
  - **회원 문의**(로그인하고 보낸 것 — `user_id`)는 같은 글이 **학생 알림함**(`student_messages`, kind `contact_reply`)으로 간다.
    제목은 `"문의 첫머리 20자…" 문의에 답변드려요`(`contactReplyMessage`, `src/lib/contact-reply.ts`). 답변 1,000자 = 알림함 본문 상한.
  - **비회원 문의**는 이 사이트로 전할 길이 없다 — 카드가 "남긴 연락처(전화 · 메일)로 직접 답하고 한 내용을 적어 두라" 고 말하고 `답변 기록하고 완료` 는 기록만 남긴다.
  - 고쳐서 다시 보내면 알림이 한 번 더 간다 (이미 보낸 알림은 지우지 않는다). 알림을 못 보내도 답변 기록은 남긴다 (숙제 점검과 같은 규칙).
- `/contact` 는 **비로그인 방문자에게** "로그인하고 문의하면 답변을 사이트 알림함으로 바로 받아요" + 로그인 · 회원가입 버튼을, 로그인한 사람에게는
  "답변은 마이페이지 → 알림으로" 를 폼 위에 적는다. 접수 뒤 문구도 둘로 갈린다 (비회원에게는 회원가입 안내).
- 문의는 여전히 비회원의 유일한 쓰기 경로라 보안 점검의 허니팟 · 길이 상한 그대로다. 학생이 자기 문의 목록을 보는 화면은 없다 (정책도 스태프만 조회) — 답은 알림함으로 간다.
