    음원 목록은 강 번호 → 같은 강 안에서는 올린 순서.
  - **음원 파일은 저장소에 그대로 올린다** (2026-09-16 Alan 확인). 외부 링크(드랍박스 등)를 쓰지 않는다 —
    수강생전용을 지키려면 private 버킷 + 서명 URL 이어야 하고, 공유 링크는 한 번 새면 누구나 받을 수 있다.
- 파일은 전부 private 버킷(`study-materials`, `homework`, `lc-audio`, `lc-textbooks`, `study-checkins`, `class-materials`). 화면은 `/files/{material|homework|audio|textbook|checkin|class|notice}/{id}` 로
  서명 URL 로 리다이렉트한다 — 행 RLS 와 storage 정책이 같은 규칙으로 막는다. 서명 주소는 10분, LC 음원 · 숙제 음성 파일은 6시간이다 (재생 중 구간 요청이 이어진다).
  **LC 교재 표지(크기를 준 것)는 48시간 · 하루 동안 모두가 같은 주소**다 — 행 RLS 가 먼저 막고 서비스 롤로 서명한다 ("화면 전환 속도" 5).
- 서버 액션 본문 한도(1MB) 때문에 파일은 **브라우저 → Storage 직접 업로드**, 서버 액션은 경로·이름만 등록한다.
  저장소 경로의 이름은 무작위 + **영문 · 숫자 1~8자 확장자만**(`objectName` · `SAFE_EXT`, `src/lib/upload.ts` — 2026-10-22 오류 점검: `사진.jpeg_large` 처럼 꼴이 다른 확장자가
  경로에 남아 비대면 자료 안내 사진이 "사진 정보가 올바르지 않아요" 로 저장되지 않았다). 형식은 경로가 아니라 파일 이름으로 정하므로 빼도 된다.
  **저장소에 적히는 형식은 파일에 붙은 형식이다** (2026-10-07 숙제 음성 파일을 열며 확인) — storage-js 는 File 을 multipart 로 보내고 `contentType` 옵션은
  File 이 아닌 본문에만 쓴다. 그래서 `uploadFile`(`src/lib/upload-client.ts`)이 정한 형식(기본은 확장자로 채운 `contentTypeOf`)이 파일의 형식과 다르면
  그 형식을 붙인 새 File 로 감싸 보낸다 (`upload-client.test.ts`). 그전에는 브라우저가 형식을 비워 준 파일(hwp · 일부 휴대폰 녹음)이 `application/octet-stream` 으로 올라가
  형식을 제한한 버킷(숙제 · 수강증 · LC 음원)에서 튕겼다.
